- `ngv2-submission-parser` -> `ngv2/submission_parser.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Exposes: FindingSubmission, parse_submission_file, scan_submission_queue, VULN_TYPE_MAP, _normalize_vuln_type, _extract_code_block, CVSS_DIM_ORDER. Contract: ngv2.submission_parser is a pure, stdlib-only (re/dataclasses/pathlib) deterministic parser that turns submission-ready markdown files into structured FindingSubmission records (the durable capability distilled from legacy huntr_submitter.py, with all Playwright/network form-filling dropped). FindingSubmission is a dataclass with string fields finding_id, title, repo_url, version, vuln_type, cwe, cvss_vector, description, poc_code (all default ''), package_manager (default 'pypi'), severity (default ''), source_file (default ''), and expected_bounty: float (default 0.0); it exposes cvss_components() -> dict mapping CVSS short-code (AV/AC/...) to value by splitting cvss_vector on '/', and validate() -> list[str] returning human-readable error strings ('missing title', 'invalid repo_url: ...', 'missing version', 'missing vuln_type', 'missing description', and 'CVSS vector missing dims: [...]' when cvss_vector is set but lacks any of CVSS_DIM_ORDER). CVSS_DIM_ORDER == ['AV','AC','PR','UI','S','C','I','A']. VULN_TYPE_MAP: dict[str,str] maps lowercased raw vuln-type strings and CWE ids (e.g. 'code injection'->'Code Injection', 'cwe-94'->'Code Injection', 'ssrf'/'cwe-918'->'Server Side Request Forgery (SSRF)', 'rce'->'Remote Code Execution', 'cwe-502'->'Deserialization of Untrusted Data', 'xss'/'cwe-79'->'Cross-Site Scripting (XSS)', 'cwe-22'->'Path Traversal', 'cwe-78'->'Command Injection') to canonical labels. _normalize_vuln_type(raw) lowercases/strips/rstrips ')' then: direct VULN_TYPE_MAP hit, else extract 'cwe-<n>' and look up, else prefix match (low startswith key or key startswith low), else return raw.strip().title(); empty input returns ''. _extract_code_block(text, start_pos) -> (content, end_pos): from start_pos matches an opening fence of 3+ backticks plus optional language to end-of-line, finds the matching closing fence (same backtick count, alone on its line) and returns inner content plus the index just past the closing fence; returns ('', start_pos) if no opening fence and (rest_of_text, len(text)) if unterminated. parse_submission_file(path: Path, finding_n: Optional[int]=None) -> List[FindingSubmission] reads the file (utf-8, errors='replace'), auto-detects format by header regex (Format A '^## FINDING \\S+' -> multi-finding split on '## FINDING N — Title' with **Repository URL:**/**Version Affected:**/**Vulnerability Type:** (with trailing CWE)/**Description:** fields and JS PoC extracted from a ```javascript fenced block in the description; Format B '^## TITLE$' -> single finding from ## TITLE/## CWE/## CVSS VECTOR/## DESCRIPTION sections; Format C '^## Target$' -> single finding), stamps source_file=str(path) on each finding, and if finding_n is given returns a 1-based single-element slice (or [] if out of range). scan_submission_queue(root: Path) -> List[FindingSubmission] walks the given directory for *.md submission files (deterministic injected root, no module-level path), parses each (skipping files that raise), de-duplicates by lowercased title, and returns findings sorted by expected_bounty descending then title ascending for a stable order. Everything is deterministic: no clock, network, randomness, or Playwright.

Contract: ngv2.js_poc_templates is a pure, deterministic, stdlib-only generator of JavaScript/Node.js PoC scaffolding templates for huntr.com submissions (no network/LLM/exploit execution — gate class pure_fuzz). It exports TEMPLATES: a dict mapping a CWE id string to a callable fn(library_name: str, vuln_description: str) -> str that returns a JS code-string template; the template MUST embed the library_name and vuln_description verbatim and be substantial (len > 100). The exact required CWE keys are: 'CWE-78','CWE-94','CWE-502','CWE-22','CWE-918','CWE-89','CWE-601','CWE-787'. SUPPORTED_CWES MUST equal sorted(TEMPLATES.keys()) (a list). run(args) takes an object with attributes cwe_type, library_name, vuln_description and returns a dict: on success {'status':'ok','cwe':<normalized upper/stripped CWE>,'library':<stripped lib>,'description':<stripped desc or default 'Vulnerability in <library>' when empty/None>,'poc_template':<the generated JS string>,'instructions':<list of 4 str submission steps>}; on an unsupported/normalized CWE not in TEMPLATES it returns {'status':'error','error':'Unsupported CWE type: <cwe>','supported_cwes':SUPPORTED_CWES}. cwe_type is normalized via .upper().strip() before lookup so 'cwe-78' and ' CWE-78 ' resolve to 'CWE-78'. run must be pure: identical args yield identical output and module-level state is never mutated. FAST_FAIL_THRESHOLD=120; MID_FAIL_THRESHOLD=600; CASCADE_MIN_FAILURES=3; CASCADE_WINDOW_S=300. classify_failure(messages:List[str])->str joins messages, regex-matches case-insensitively against ERROR_PATTERNS, returns the category with the most pattern hits ('unknown' if none; - `ngv2-dedup-novelty` -> `ngv2/dedup_novelty.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Exposes: tokenize, jaccard_similarity, weighted_similarity, check_duplicate, STOPWORDS, make_scripted_fetcher. Contract: ngv2.dedup_novelty is a pure, deterministic, stdlib-only similarity/novelty layer distilled from the legacy dedup_checker. It exports: STOPWORDS (a frozenset of lowercase stopwords including at least 'the','via','using','allows','with','in','of'); tokenize(text)->set[str] which lowercases, strips ASCII punctuation (string.punctuation), splits on whitespace, and drops both stopwords and tokens of length<=1, returning a set; jaccard_similarity(set_a,set_b)->float = |a&b|/|a|b| with 0.0 when the union is empty (including both-empty); weighted_similarity(query_tokens,title_tokens)->float = 0.0 if either set is empty else (jaccard + coverage)/2 where coverage=|query&title|/|query|; check_duplicate(owner_repo, finding_title, existing_titles=None, threshold=0.6, fetcher=None)->dict — a pure shell that, when existing_titles is None, calls the INJECTED fetcher(owner_repo)->list[str] seam (defaulting to no matches / empty list when fetcher is also None; the real network fetch lives at runtime and is never invoked in tests). It scores finding_title against every existing title via weighted_similarity, keeps only matches with score>0.1, sorts descending by similarity_score, takes the top 5, sets max_similarity=top score rounded to 3 (0.0 if none), is_duplicate = max_similarity>=threshold, and recommendation='skip' if duplicate, 'review' if max_similarity>=threshold*0.7, else 'submit'. The returned dict ALWAYS contains keys: status('ok'), repo, finding_title, existing_count, is_duplicate(bool), max_similarity(float), threshold, similar_titles(list of dicts each with title, similarity_score(rounded 3), matching_words(sorted list)), recommendation(one of 'skip'|'review'|'submit'), reason(str). The empty-existing case returns existing_count=0, is_duplicate=False, recommendation='submit', similar_titles=[]. Also exports make_scripted_fetcher(mapping: dict[str,list[str]]) returning a deterministic callable(owner_repo)->list[str] (empty list for unknown repos) for use as the injected seam.
- `ngv2-submission-readiness` -> `ngv2/submission_readiness.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Contract: ngv2.submission_readiness is a pure, stdlib-only deterministic submission-readiness scorer for NobleGreedv2. It exposes a frozen-shape dataclass ArtifactCheck(exists: bool, path: Optional[str]=None, note: str='') and a dataclass FindingScore with fields in this exact order: id:str, task_id:int, finding_id:int, amount_usd:float, cwe:str, severity:str, repo:str, status:str, description:str, submission_pkg:ArtifactCheck (default ArtifactCheck(False)), poc_file:ArtifactCheck (default ArtifactCheck(False)), live_test:ArtifactCheck (default ArtifactCheck(False)), readiness_score:int=0, next_action:str='', submission_rank:int=0. The three artifact checkers — check_submission_pkg(f, resolver)->ArtifactCheck, check_poc(f, resolver)->ArtifactCheck, check_live_test(f, resolver)->ArtifactCheck — take the FindingScore plus an INJECTED resolver callable resolver(kind: str, f: FindingScore) -> Optional[str] (kind in {'submission_pkg','poc','live_test'}); a non-None/non-empty string return means the artifact exists at that path (ArtifactCheck(True, path)), else ArtifactCheck(False, None, <kind-specific note>). make_mock_artifact_resolver(mapping: dict) -> resolver builds a deterministic resolver from a dict keyed by (kind) or (kind, finding_id) returning the mapped path string (or None when absent); the real filesystem scan lives at NGv2 runtime and is never invoked by the oracle. score_finding(f, resolver=None)->FindingScore populates the three ArtifactCheck fields via the checkers (using an injected resolver; resolver=None means all artifacts absent), sets readiness_score = exactly the count of present artifacts (0..3, sum of the three .exists booleans), sets next_action to a deterministic string drawn from the NEXT_ACTIONS dict (keys: ('SUBMIT'), and per missing-set keys described below), and sets submission_rank = int((10000 - amount_usd) * 10 + (3 - readiness_score)) (lower rank = higher priority). NEXT_ACTIONS is a dict mapping logical keys to fixed plain-ASCII action strings: 'SUBMIT' (all 3 present), 'NEED_PKG', 'NEED_POC', 'NEED_TEST' (exactly one missing), and 'NEED_ALL' (zero present) plus partial keys; score_finding must select 'SUBMIT' when score==3, the single NEED_* matching the one missing artifact when score==2, and 'NEED_ALL' when score==0. READINESS_FIELDS is a tuple of the FindingScore field names in declaration order. load_ledger(entries: list[dict], *, skip_statuses=('blocked_no_platform',)) -> list[FindingScore] converts a list of plain ledger-entry dicts into FindingScore objects, coercing task_id/finding_id to int (0 on missing/falsy), amount_usd to float (0.0 default), filling string fields from keys id/cwe/severity/repo/status/description (repo falls back to the 'format' key then ''), and skipping entries whose status is in skip_statuses or that are not dicts; the function never touches the filesystem, network, clock, or randomness.
