# Title

EDIT (whole-file) `tools/webui_control.py` + `tools/webui_server.py` + `tools/webui_static/app.js` to (a) serve the typed config schema and a server-side-validated atomic typed-save on the REAL stdlib-http.server operator sidecar, and (b) render the schema as the correct widgets (number/text/checkbox/enum-dropdown/path-with-Browse), a model-selection dropdown per role with twin selects for dual-agent roles, an API-key input per provider, provider-locked (disabled) options when keyless, and a Save action that persists atomically. This targets the LIVE WebUI (`tools/webui_server.py`, currently run as `python -m tools.webui_server --host 127.0.0.1 --port 8765 --state-dir state --logs-dir logs`), NOT the dead Flask tree `webui/app.py`.

# Scope

This WebUI is a stdlib `http.server` sidecar (NOT Flask). GET routes are dispatched in `tools/webui_server.py:WebUIHandler._dispatch_get`; mutations (POST/PUT) flow through `_dispatch_mutation`, are auth-gated (`X-Operator-Token` + single-use `X-CSRF-Nonce`), and resolve to `ControlHandlers` methods (in `tools/webui_control.py`) named in the class-attribute dispatch tables `_dispatch_post` / `_dispatch_put`; each handler returns a `(status:int, body:dict)` tuple. The frontend is a vanilla-JS SPA in `tools/webui_static/` (`index.html` + `app.js` + `styles.css`), served at `/` and `/static/...`, with a hash-routed `#/config` page (`pages.config` in `app.js`) and an `api(path, opts)` fetch wrapper that already attaches the operator token + mints a CSRF nonce for POST/PUT.

EDIT `tools/webui_control.py` (whole-file; NOT on `_NEVER_AUTO_APPROVE`), ADD NEW class methods to `ControlHandlers` as ADDITIVE nodes (do NOT rewrite existing method bodies — never-patch-class-methods; the orchestrator AST-merges new methods + dispatch-table extensions):
- `get_config_schema(self) -> (int, dict)`: import `harness.webui_config_schema` (`CONFIG_FIELDS`, `ROLES`, `PROVIDERS`) and `harness.secrets_store` (`load_secrets`). Read the current `harness/config.yaml` (via `self.repo_root / 'harness' / 'config.yaml'`, the same path `get_config()` uses). Return `(200, {"fields": [...], "roles": [...], "providers": {...}, "values": {<config_key>: <current>}, "keys_present": [<api_key_env names with a non-empty secret>]})`. Serialize `ConfigField`/`RoleSpec`/`ProviderSpec` to plain dicts (`name`, `dtype`, bounds/choices; `config_key`, `dual`; `api_backed`, `api_key_env`) so JSON-encodable. `keys_present` is computed from `load_secrets(self.state_dir)` so the client can disable keyless api-backed provider options.
- `post_save_typed_config(self, body: dict) -> (int, dict)`: the submitted form arrives as a JSON object (keys like `parallel_cap`, `synthesis.active_agents` (list), `overseer.default_backend`, `control.autobrief_default_agent`, and `api_key__<ENV>` for any submitted provider key). FIRST persist every non-empty `api_key__<ENV>` value via `secrets_store.save_secret(self.state_dir, <ENV>, value)`; then `secrets = load_secrets(self.state_dir)`; then call `validate_config(submitted, secrets=secrets)` (strip the `api_key__*` keys before passing if the schema doesn't expect them). On `ConfigValidationError` return `(400, {"field_errors": err.field_errors})` WITHOUT writing config. On success call `atomic_save_config(validated, self.repo_root / 'harness' / 'config.yaml')` and return `(200, {"saved": True})`. NEVER echo any key value back in the response and NEVER write it to config.yaml.

(GET /api/config/schema is read-only; it is gated only when `auth_required_for_reads` is set, like every other GET.)
