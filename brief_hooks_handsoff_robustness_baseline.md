# Title

Close the hands-off robustness gaps surfaced by the pre-existing test baseline (so autowork.enabled survives unattended for days)

# Scope

Triage of the 21 baseline test failures (2026-06-05): 11 PASS in isolation (non-hermetic ordering artifacts — no production impact) and the rest are config-posture guards or test-infra drift, EXCEPT three that genuinely affect fully-hands-off operation. Fix these three; update the stale guards so the baseline is clean enough that a real regression is not masked.

ITEM 1 (HIGH — the #1 documented hands-off killer) — bounded, stale-aware commit-lock acquisition. RED oracle ALREADY EXISTS: tests/test_commit_lock_reclaim.py asserts `harness/autowork_daemon._acquire_commit_lock_or_reclaim(state_dir, deadline_sec=...)` which DOES NOT EXIST yet. Without it a stale 0-byte `state/control/autowork/git_commit.lock` (left by a dead prior session) WEDGES the daemon -> watchdog escalates -> wasteful self-heal spend; the daemon cannot self-recover unattended. Implement it per the oracle: free lock -> acquire + stamp owner PID -> (fd, 'acquired'); recorded owner PID NOT alive -> reclaim the stale lock -> (fd, 'reclaimed'); a LIVE holder -> (None, 'busy') WITHOUT blocking (bounded by deadline_sec, elapsed << blocking). Rewire `_maybe_push_and_rebase_pin` (and any other unconditional flock of git_commit.lock on the daemon path) to use it (busy -> skip this tick, never hang). harness/autowork_daemon.py is DENY-LISTED -> operator-land (harness_self_fix; lands hands-off once GAP1/GAP2 from brief_hooks_autoapprove_harness_commit_path are in).

ITEM 2 (MEDIUM — commit-path robustness) — untracked test poisons a patches commit. tests/adversarial/test_apply_scope_gate_adversarial.py::TestC6UntrackedTestPoisonsPatches is RED: when a task emits state/output/<id>.patches.json AND an untracked tests/test_*.py exists in the parent worktree, commit_accepted_output (harness/git_integration.py ~:54-98) synthesizes a .files.json manifest that INCLUDES the untracked test, the patches dispatch (gi ~:676) is never reached, and the synthesized manifest fails the §1b membership check (untracked test ∉ allowed_files) -> commit rejected. Fix: when a .patches.json sidecar exists for the task, the patches dispatch MUST take precedence and the untracked-test manifest-synthesis MUST NOT clobber it (or must restrict the synthesized manifest to allowed_files). harness/git_integration.py is DENY-LISTED -> operator-land.

ITEM 3 (MEDIUM — unattended planning-failure visibility) — planner subprocess stderr is not surfaced. tests/adversarial/test_planner_stderr_tail.py::test_run_planner_subprocess_returns_three_tuple is RED: the planner-subprocess wrapper must return a 3-tuple carrying a stderr_tail so a hands-off planning failure is diagnosable in the ledger rather than silent. The test brief currently fails load ("Brief load failed: Validation failed") before the sentinel path — confirm whether the regression is in the wrapper's stderr capture or only the test fixture; fix the real one. harness/planner/** is NOT deny-listed.
