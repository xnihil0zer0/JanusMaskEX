- `ngv2-permission-model` -> `ngv2/permission_model.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Exposes: PermissionMode, PermissionPolicy, PermissionEnforcer, EnforcementResult, WORKER_WRITE_SCOPES, WORKER_PERMISSION_MODES, DEFAULT_TOOL_REQUIREMENTS. Contract: ngv2.permission_model is a pure, stdlib-only graduated permission model for NobleGreedv2 workers. It exports an IntEnum PermissionMode with members READ_ONLY=1, WORKSPACE_WRITE=2, ALLOW=3, DANGER_FULL_ACCESS=4, PROMPT=5 (higher value = more privilege; ordering comparisons must hold). WORKER_PERMISSION_MODES maps worker-type str -> PermissionMode ({'simple':READ_ONLY,'eval':WORKSPACE_WRITE,'hunt':WORKSPACE_WRITE,'adversarial':WORKSPACE_WRITE,'gpu':WORKSPACE_WRITE,'overseer':ALLOW}). WORKER_WRITE_SCOPES maps worker-type str -> list[str] of relative write-path prefixes or None for unrestricted ('simple':[], 'overseer':None, 'hunt' includes 'tmp/'). EnforcementResult is a dataclass(allowed:bool, tool:str='', active_mode:str='', required_mode:str='', reason:str='') with staticmethods allow() and deny(tool,active_mode,required_mode,reason). PermissionPolicy is a dataclass(active_mode:PermissionMode, workspace_root:Path, allowed_paths:list[str], tool_requirements:dict[str,PermissionMode]=copy of DEFAULT_TOOL_REQUIREMENTS) with classmethods for_worker_type(worker_type, workspace_root=None) and from_manifest(manifest, workspace_root=None); for_worker_type uses WORKER_PERMISSION_MODES/WORKER_WRITE_SCOPES (unknown type -> WORKSPACE_WRITE, None scopes -> [] allowed_paths), from_manifest reads manifest['permission_level'] (string keys read_only/workspace_write/allow/danger_full_access, default workspace_write) and manifest['workspace_paths'] (default []). PermissionEnforcer(policy) provides check_tool(tool_name, input_args=None)->EnforcementResult (looks up policy.tool_requirements, unknown tool requires WORKSPACE_WRITE, allowed iff active_mode>=required, deny sets active_mode/required_mode to the .name strings), check_file_write(path:str|Path)->EnforcementResult (ALLOW+ unrestricted within workspace_root; READ_ONLY denies all writes; WORKSPACE_WRITE must be within workspace_root AND, if allowed_paths nonempty, under one of workspace_root/allowed_rel; empty allowed_paths means unrestricted within root; paths escaping workspace_root are denied), and check_bash(command:str)->EnforcementResult (ALLOW+ allows everything; WORKSPACE_WRITE allows everything; READ_ONLY applies a heuristic: deny on write redirections >/>> and in-place flags -i/--in-place, allow first-command names in a read-only allowlist incl ls/cat/grep/echo, git allowed only for read-only subcommands like status/log/diff, deny unknown commands; env-var assignments and sudo are skipped when extracting the first command). All checks are deterministic with no clock/network/random/IO beyond Path.resolve.
- `ngv2-bash-validator` -> `ngv2/bash_validator.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Exposes: PermissionMode, CommandIntent, ValidationResult, validate_command, validate_read_only, check_destructive, validate_mode, validate_sed, validate_paths, classify_command, extract_first_command. Contract: ngv2/bash_validator.py is a pure, deterministic, stdlib-only bash-command validation pipeline (no subprocess/network/LLM — it only inspects the command STRING). It exports two enums: PermissionMode (an Enum with members READ_ONLY=1, WORKSPACE_WRITE=2, DANGER_FULL_ACCESS=3, PROMPT=4, ALLOW=5) and CommandIntent (an Enum with members READ_ONLY, WRITE, DESTRUCTIVE, NETWORK, PROCESS_MANAGEMENT, PACKAGE_MANAGEMENT, SYSTEM_ADMIN, UNKNOWN). ValidationResult is a helper class with three @staticmethod factories returning plain dicts: allow() -> {'result': 'allow'}, block(reason) -> {'result': 'block', 'reason': reason}, warn(message) -> {'result': 'warn', 'message': message}. extract_first_command(command: str) -> str strips leading KEY=value env-var assignments and returns the first bare command token ('' if none). The six validation functions each return a result dict with a 'result' key whose value is one of 'allow'/'block'/'warn' (block dicts carry 'reason', warn dicts carry 'message'): validate_read_only(command, mode) blocks write/state-modifying commands, write redirections (>, >>, >&), sudo-wrapped writes, and non-read-only git subcommands ONLY when mode is READ_ONLY (otherwise allow); check_destructive(command) warns on known destructive patterns (e.g. 'rm -rf /'), always-destructive commands (shred, wipefs), and any rm invocation carrying both -r and -f flags (combined or space-separated); validate_mode(command, mode) delegates to validate_read_only for READ_ONLY, warns when a WORKSPACE_WRITE command targets system paths, and allows for DANGER_FULL_ACCESS/PROMPT/ALLOW; validate_sed(command, mode) blocks 'sed -i' in READ_ONLY mode and allows otherwise; validate_paths(command, workspace: Path) warns on '../' traversal outside workspace and on '~/'/'$HOME' references, and blocks 'git clone' to /tmp/. classify_command(command) -> CommandIntent returns one of the 8 intents, with special cases: rm -> DESTRUCTIVE, 'sed -i' -> WRITE, and git classified READ_ONLY/WRITE by subcommand. validate_command(command, mode, workspace) runs the pipeline in order validate_mode -> validate_sed -> check_destructive -> validate_paths and returns the FIRST non-allow result, else allow().
- `ngv2-prompt-integrity` -> `ngv2/prompt_integrity.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Exposes: build_registry, save_registry, load_registry, update_registry, verify_file, verify_all, compute_hash, PROTECTED_FILES. Contract: ngv2.prompt_integrity is a deterministic, stdlib-only SHA-256 integrity registry for protected prompt/template files, distilled from the legacy services/prompt_integrity.py. It exposes module constant PROTECTED_FILES (a list[str] of relative paths to guard) and these functions: compute_hash(filepath: str) -> str returns the lowercase hex SHA-256 digest of a file's bytes (must equal hashlib.sha256(open(filepath,'rb').read()).hexdigest()), reading in chunks so it handles arbitrary sizes; build_registry(base_dir: str = None) -> dict computes hashes for every entry in PROTECTED_FILES that exists on disk under base_dir (missing files are silently skipped, never raised) and returns a dict of exact shape {'version': 1, 'updated_at': <ISO8601 str>, 'hashes': {rel_path: {'sha256': <hex>, 'updated_at': <ISO8601 str>}}} (only existing files appear under 'hashes'); save_registry(registry: dict, path: str = None) -> None atomically writes the registry as indent=2 JSON (creating parent dirs as needed); load_registry(path: str = None) -> dict reads it back, returning {} (empty dict, never raising) if the file is missing or unparseable (fail-open); update_registry(base_dir: str = None) -> dict is build_registry followed by save_registry, returning the built registry; verify_file(filepath: str, registry: dict = None) -> tuple[bool, str] checks one relative path against the registry returning (ok, message) where an empty/keyless registry -> (True, 'no registry'), a path not present in registry['hashes'] -> (True, 'not registered'), a matching hash -> (True, 'ok'), a file missing from disk -> (False, message containing 'INTEGRITY VIOLATION' and 'missing'), and a hash mismatch -> (False, message containing 'INTEGRITY VIOLATION' and 'mismatch'); verify_all(base_dir: str = None, registry: dict = None) -> list[dict] verifies every path recorded under registry['hashes'] and returns a list of violation dicts (empty list == all clean), each shaped {'file': <rel_path>, 'status': 'mismatch'|'missing'|'error', 'message': <str>}, returning [] for an empty/missing registry (fail-open). base_dir defaults are derived so callers may pass an explicit directory; verify_file/verify_all resolve protected files relative to the registry's recorded relative keys. All behavior is deterministic and dependency-free (hashlib/json/os/tempfile/datetime only).
- `ngv2-safety-framework` -> `ngv2/safety_framework.py` (gate: stateful_fuzz; meta_task_type: stateful_fuzz). Exposes: circuit_breaker_check, circuit_breaker_trip, circuit_breaker_reset, quarantine_status, quarantine_record, validate_json, health_check, load_safety_state, save_safety_state, make_scripted_probes, MAX_CONSECUTIVE_FAILURES, QUARANTINE_USES. Contract: ngv2.safety_framework is a deterministic, stdlib-only safety state machine with an injected-seam shell — no clock, network, subprocess, or global on-disk state in its tested paths. Constants: MAX_CONSECUTIVE_FAILURES == 3, QUARANTINE_USES == 5, and SCHEMA_CHECKS a dict mapping relative file paths to {"required_keys": [...], "types": {key: type}} schemas (must include keys "orchestrator/state.json" and "data/tool_catalog.json"). State persistence: load_safety_state(state_path: str) -> dict returns the parsed JSON if the file exists else the empty shell {"circuit_breakers": {}, "quarantine": {}, "updated_at": None}; save_safety_state(state: dict, state_path: str, now: str = "") -> None writes indent=2 JSON, creating parent dirs, and sets state["updated_at"] = now (caller-supplied timestamp string, default "" — never calls datetime.now). Circuit breaker (all take state_path: str): circuit_breaker_check(tool_name, state_path) -> {"tool", "tripped" (bool, True iff consecutive_failures >= MAX_CONSECUTIVE_FAILURES), "consecutive_failures" (int), "last_error" (str), "tripped_at" (str)} with safe defaults for unknown tools (consecutive_failures 0, tripped False); circuit_breaker_trip(tool_name, error_msg, state_path, now="") -> None increments consecutive_failures and total_failures, sets last_error = error_msg[:500], and on reaching the threshold sets tripped_at = now, persisting via save_safety_state; circuit_breaker_reset(tool_name, state_path) -> None zeroes consecutive_failures and clears tripped_at for an existing tool (no-op if absent). Quarantine (take state_path: str): quarantine_status(tool_name, state_path) -> {"tool", "in_quarantine" (bool, True iff uses < QUARANTINE_USES), "uses" (int), "successes" (int), "remaining" (int = max(0, QUARANTINE_USES - uses)), "success_rate" (float = successes/uses, 0 when uses==0)}; quarantine_record(tool_name, outcome, state_path, now="") -> None increments uses and (iff outcome == "success") successes, persisting. validate_json(file_path: str, rel_path: str = "") -> {"file" (the rel_path used for schema lookup, falling back to file_path), "valid" (bool), "errors" (list[str])}: returns valid False with a "File not found"-prefixed error if missing, valid False with a "JSON parse error"-prefixed error on malformed JSON, and for a matched SCHEMA_CHECKS entry appends "Missing required key: <k>" for absent required keys and "Type mismatch: <k> should be <type>" for wrong types, valid True with empty errors when all pass or no schema matches. health_check(probes: dict) -> dict is PURE over an injected probes mapping (no subprocess/disk): it consumes probe results and returns {"checks": list of {"check": str, "status": one of "pass"/"warn"/"fail"/"error", ...}, "overall": "UNHEALTHY" if any check status is "fail" else "DEGRADED" if any is "warn" else "HEALTHY"}. make_scripted_probes(checks: list) -> dict is a helper building a valid probes payload from a list of pre-shaped check dicts for use with health_check. All functions are deterministic and side-effect-free except save/trip/record/reset which write only to the caller-supplied state_path.
- `ngv2-prompt-hints` -> `ngv2/prompt_hints.py` (gate: pure_fuzz; meta_task_type: data_model (bypass_fuzzer, smoke-gated)). Exposes: get_hints_section, add_hint, list_hints, prune_hint, init_hints, review_all_hints, HINTS_HEADER, HINTS_MARKER, MAX_HINTS, MIN_HINT_LEN. Contract: ngv2.prompt_hints is a pure, stdlib-only manager for an append-only "Operational Hints" section inside a prompt Markdown file. Constants: HINTS_MARKER == '## Operational Hints' (the section anchor substring), HINTS_HEADER is the full section-opening block that begins with '\n\n' and contains HINTS_MARKER and ends with two trailing newlines, MAX_HINTS == 20, MIN_HINT_LEN == 10. get_hints_section(prompt_path: str) -> tuple[str, list[str]] reads the file and returns (text_before_marker, hints); a missing file returns ('', []); a file with no marker returns (full_text, []); otherwise hints are every line within the section that, after stripping, starts with '- ', with the leading '- ' removed. list_hints(prompt_path: str) -> list[str] returns just the hints. init_hints(prompt_path: str) -> bool appends HINTS_HEADER (after rstrip of existing text) and returns True if the file exists and has no marker yet; returns False if the file is missing or the marker already exists. add_hint(prompt_path: str, hint: str, source: str) -> bool strips the hint and returns False (no file change) when: the file is missing, the stripped hint length < MIN_HINT_LEN, the hint is a case-insensitive substring duplicate of (or superstring of) an existing hint, or the section already holds MAX_HINTS hints; otherwise it appends a '- <hint>' line (creating the section via HINTS_HEADER if absent) and returns True. prune_hint(prompt_path: str, hint_number: int) -> bool removes the 1-indexed hint and rewrites the section, returning False for out-of-range numbers (< 1 or > len(hints)) with no file change, True on success. review_all_hints(prompts_dir: str) -> dict scans prompts_dir for '*.md' files (sorted by name) and returns an ordered dict mapping filename (basename) -> non-empty hints list, omitting files with no hints.
