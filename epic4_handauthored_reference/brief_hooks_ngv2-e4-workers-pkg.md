- `ngv2-agent-registry` -> `ngv2/agent_registry.py` (gate: stateful_fuzz; meta_task_type: stateful_fuzz). Exposes: AgentRegistry, AGENT_STATUSES, AGENT_STALE_THRESHOLD_S. Contract: ngv2.agent_registry exposes an AgentRegistry class — a deterministic, stdlib-only (sqlite3) registry of sub-agents and inter-agent messages, mirroring the ngv2.worker_registry pattern with time as the single injected seam. Constructor: AgentRegistry(db_path, now_fn=lambda: epoch_seconds_float) where now_fn() -> float supplies the clock for staleness/expiry (no real clock, no PID probing, no signals, no psutil — purely a SQLite state machine over two tables, agent_registry and agent_messages). Module constants: AGENT_STATUSES == ('running','completed','failed') and AGENT_STALE_THRESHOLD_S == 1800. Methods (signatures exact): register_agent(agent_id: str, worker_id: int, session_id: str, agent_type: str='', role: Optional[str]=None) -> bool — inserts a new agent with status 'running', registered_at=last_seen=now; returns True on insert, False if agent_id already exists (no exception). complete_agent(agent_id: str, status: str='completed') -> bool — sets status (coerced to 'completed' if not in ('completed','failed')) plus finished_at=last_seen=now; returns True iff the agent existed. agent_heartbeat(agent_id: str) -> bool — sets last_seen=now only for a still-running agent; returns True iff a running agent was updated. list_agents(worker_id: Optional[int]=None, status: Optional[str]=None, role: Optional[str]=None) -> list[dict] — returns agent rows as dicts (keys: agent_id, worker_id, session_id, agent_type, role, status, registered_at, last_seen, finished_at) ordered by registered_at DESC, filtered by any provided non-None criterion (worker_id of 0 is treated as no filter). send_agent_message(to_agent: str, message: str, from_agent: str='', expires_in_seconds: int=300) -> int — queues a message (created_at=now, expires_at=now+expires_in_seconds, or no expiry when expires_in_seconds<=0) and returns its new integer id (>0, monotonic). get_agent_messages(agent_id: str, mark_read: bool=True) -> list[dict] — returns the unread, non-expired messages for agent_id (keys: id, to_agent, from_agent, message, created_at, read_at, expires_at) ordered by id ASC; when mark_read is True it stamps read_at=now so a second call returns []; expired messages are never returned. set_agent_role(agent_id: str, role: str) -> bool — updates role; returns True iff the agent existed. cleanup_stale_agents(threshold_s: int=1800) -> int — marks as 'failed' (finished_at=now) every still-running agent whose last_seen is older than now-threshold_s, and returns the count transitioned. All durations/timestamps are derived from now_fn so behavior is fully deterministic under a scripted clock.
- `ngv2-work-intent-tracking` -> `ngv2/work_intent_tracking.py` (gate: stateful_fuzz; meta_task_type: stateful_fuzz). Exposes: INTENT_TYPES, WorkIntentTracker, register_intent, check_intent_collision. Contract: ngv2.work_intent_tracking is a deterministic coordination layer over the built ngv2.worker_registry.WorkerRegistry that prevents two RUNNING workers from doing the same kind of work on the same target. It exposes INTENT_TYPES = ('audit','clone','poc','live_test','hunt','submit') (an exact, ordered tuple of the valid intent categories). The public surface is the class WorkIntentTracker(registry) — constructed with a WorkerRegistry instance (the injected durable seam; no clock/network/random of its own) — plus two thin module-level helpers register_intent(registry, worker_id, intent_type, target) and check_intent_collision(registry, intent_type, target, exclude_worker_id=None) that delegate to a tracker built over the given registry. WorkIntentTracker.register_intent(worker_id: int, intent_type: str, target: str) -> int validates that intent_type is in INTENT_TYPES (raising ValueError for unknown types, before any DB write) and that target is a non-empty str (raising ValueError otherwise), then records the intent via the underlying registry and returns a positive integer intent_id. WorkIntentTracker.check_intent_collision(intent_type: str, target: str, exclude_worker_id: Optional[int] = None) -> Optional[dict] returns the existing intent dict (at minimum containing keys 'worker_id', 'intent_type', 'target') when another RUNNING worker already holds that exact (intent_type, target) pair, or None when free; an unknown intent_type also raises ValueError. An intent only collides while its owning worker is status='running' — completing the worker (registry.complete_worker) clears its intents so the pair becomes free again — and exclude_worker_id, when provided, suppresses collisions from that worker so it may re-register its own intent without a false positive. The module performs NO process probing, NO signals, NO live exploit/LLM/network calls; all determinism comes from the injected registry (which itself takes an injected now_fn).
- `ngv2-worker-command-dispatch` -> `ngv2/worker_command_dispatch.py` (gate: stateful_fuzz; meta_task_type: stateful_fuzz). Exposes: issue_command, get_pending_commands, mark_command_processed, broadcast_rate_limit, COMMAND_FIELDS, VALID_COMMANDS, init_db. Contract: ngv2.worker_command_dispatch is a deterministic, stdlib-only (sqlite3) overseer->worker command-delivery shell over a `worker_commands` SQLite table, mirroring the durable legacy capability. The injected seam is a `db_path` parameter (a pathlib.Path / str to a SQLite file) accepted by every function; tests pass a tempfile so no real state is touched and there is no live network/clock dependency in the contract surface (time-derived expiry is computed internally but the oracle only asserts ordering/relative semantics, never wall-clock values). Exports: `init_db(db_path) -> None` creates the table idempotently with columns id, worker_id, command, issued_at, expires_at, processed_at, issued_by. `COMMAND_FIELDS` is the exact tuple ('id','worker_id','command','issued_at','expires_at','processed_at','issued_by'). `VALID_COMMANDS` is the frozenset/tuple of accepted base commands {'pause','resume','abort','checkpoint','rate_limit_backoff'} (the rate_limit_backoff form carries a ':<delay_seconds>' suffix). `issue_command(worker_id:int, command:str, expires_in_seconds:int=300, issued_by:str='overseer', db_path=...) -> int` inserts one command row (auto-increment id returned), stamping issued_at (ISO8601) and expires_at = issued_at+expires_in_seconds (None when expires_in_seconds<=0); it must reject malformed commands not in VALID_COMMANDS (raising ValueError). `get_pending_commands(worker_id:int, db_path=...) -> list[dict]` returns unprocessed, non-expired rows for that worker ordered by id ascending, each a dict with exactly COMMAND_FIELDS keys. `mark_command_processed(command_id:int, db_path=...) -> None` sets processed_at so the row no longer appears as pending (idempotent). `broadcast_rate_limit(worker_ids, delay_seconds:int=120, exclude_worker_id:Optional[int]=None, db_path=...) -> int` issues 'rate_limit_backoff:<delay_seconds>' to each given running worker id except exclude_worker_id, returning the count issued. All functions are pure with respect to their inputs apart from the explicit db_path side effect.
- `ngv2-log-watcher` -> `ngv2/log_watcher.py` (gate: stateful_fuzz; meta_task_type: stateful_fuzz). Contract: ngv2.log_watcher is a deterministic, stdlib-only (json/pathlib/datetime/collections.defaultdict) log-watching rule engine for the NobleGreedv2 overseer. It reads a JSONL progress window, applies three guarded rules, and emits overseer signals; all external effects go through an injected sink so JM never performs live dispatch. Rule 'rate_limit' fires at most once per run when some event has status-or-phase lowercased == 'error' AND 'rate limit' in its lowercased message, OR rl_state.get('is_limited') is truthy; suppressed if ctrl_state's 'rate_limit_broadcast_at' ISO timestamp is within RATE_LIMIT_COOLDOWN_S of now. Rule 'critical_finding' fires once per distinct task_id when 'CRITICAL' is in event message AND status-or-phase == 'finding' AND task_id is not None; suppressed if str(task_id) is a key in ctrl_state['critical_dispatched']. Rule 'bash_failure_x3' fires once per distinct task_id whose bash_failure count in the window is >= BASH_FAIL_THRESHOLD; suppressed if task_id is in ctrl_state['bash_escalated']. When not dry_run and ctrl_state is not None, apply_rules records firings into ctrl_state (sets rate_limit_broadcast_at to an ISO string, adds str(task_id) keys to critical_dispatched dict, appends task_id to bash_escalated list). action_broadcast_rate_limit(delay=120, dry_run=False, *, sink=None) -> None, action_dispatch_live_test(task_id, dry_run=False, *, sink=None) -> None, action_escalate(task_id, failure_cnt, dry_run=False, *, sink=None) -> None are pure executors that (unless dry_run) emit one signal dict via the injected sink: escalate emits {'signal':'escalate','task_id':task_id,'failure_count':failure_cnt}. RULES is a dict mapping the three rule_name strings to their action callables: {'rate_limit': action_broadcast_rate_limit, 'critical_finding': action_dispatch_live_test, 'bash_failure_x3': action_escalate}.
