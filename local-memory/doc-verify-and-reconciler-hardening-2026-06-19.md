The planner stamps the **raw-bytes** sha, so NORMAL hands-off operation is SAFE (`stamped==current` → skip). The 023a468 hardening: when the sha-stale brief's slug IS allowlisted, archive the STALE PLAN instead (so it re-plans), keep the brief; un-allowlisted stale briefs still archived. ★Operator lesson: don't hand-edit a live allowlisted brief mid-flight (pre-023a468 = silent eviction; now = clean re-plan). ★To recover a wrongly-archived fresh brief: `mv` brief+plan back to root; if the plan's sha is stale, DELETE the plan so it re-plans fresh (a sha-mismatched plan won't extract).
