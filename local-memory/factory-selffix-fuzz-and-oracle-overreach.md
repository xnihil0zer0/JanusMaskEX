🧱 BLOCKER CHAIN discovered 2026-06-24 while fixing the planner NEW-MODULE red-pair inversion (needed to unblock P2.1 epic c0+; see [[ngv2-closure-program-active-2026-06-24]]).

**THE ROOT BUG (validated, fix known):** `harness/planner/plan_normalizer.py::_enforce_module_first` (:142-203) INVERTS a correctly-authored NEW-module red-pair to `oracle.deps=[impl], impl.deps=[]` (deadlock: impl fires before the oracle authors its test). Cause: the fix-forward carve-out (:173-179) requires the module to EXIST on disk (`is_file()` :176); a brand-new module fails it → flip at :180-188. Validator `plan_validator.py:202-215` simultaneously REQUIRES the oracle's mutation_target to name that exact new module → the two rules are contradictory for new-module red-pairs. **FIX (validated 9/11, monkeypatch in `_autowork_scratch/planner_redpair_inversion/validate_oracle_satisfiable.py`):** drop the `repo_root is not None` + `is_file()` preconditions from the `_vc` carve-out so it fires whenever the impl's verification_command substring-names an oracle authored test file (regardless of on-disk existence). ACCEPTANCE-SAFE: new-module RED oracles accept via direction-agnostic `orchestrator._new_module_red_by_absence` (:2126); existing no-`is_file()` sibling `_sanitize_impl_verification_commands` (:268-290) already uses this signal. NARROW: a genuine non-red-pair (impl vc NOT naming oracle test) STILL inverts.

**META-DEFECT 1 — harness_self_fix now runs the differential fuzzer, which FAILS on mismatched candidate shapes.** The difffuzz restoration flipped `harness_self_fix` (+orchestration/harness_plumbing/planner_tooling/validation) from `bypass_fuzzer:True`→`False` (commit `84a877c`). **README §9 is STALE** (still lists harness_self_fix as bypass). So harness self-fixes now go through `diff_fuzzer.fuzz_from_task`. When the two agents emit DIFFERENT shapes (Claude whole-file rewrite vs Gemini `__JANUSMASK_PATCHES__` patch), `_patched_symbol_candidates` bails (diff_fuzzer.py:483 `if not info_a or not info_b: return None`), the whole-file fallback `_get_primary_function` picks the file's FIRST def (e.g. `_module_path`, NOT the target `_enforce_module_first`), and the one-sided mismatch fails closed → `fuzz_error` (deterministic, sub-ms, total_inputs=0, logged in `logs/fuzz_results/<task>_round1.json`). Sibling `nodiff-not-integrated-impl` LANDED only because BOTH agents patched. **Mitigation (fragile):** brief must FORBID whole-file/manifest explicitly + mandate `__JANUSMASK_PATCHES__` symbol patch, with the fuzzer-symmetry rationale, so both agents patch (then the correct target `_enforce_module_first(tasks:List[Dict],...)` is picked, build_input_strategy fails on List[Dict] → SKIP CLEANLY → passes). **Durable fix (option C, deferred):** make `fuzz_from_task` derive func_name from the patch side when EITHER candidate is a single-symbol patch, instead of `_get_primary_function`-of-whole-file. Genuine recurring harness defect.

**META-DEFECT 2 — test_authoring over-reach yields UNSATISFIABLE oracles.** The committed oracle `tests/harness/test_redpair_newmodule_order.py` (commit `789cde1`) authored 11 tests; 2 (`multiple_oracles_one_impl`, `unrelated_tasks`) assert OTHER normalizer behavior (dedup of same-mutation_target oracles; dangling-dep cleanup) that NO correct `_enforce_module_first` fix can satisfy → impl can't pass its vcmd. Fix: re-author the oracle with a TIGHT spec (test ONLY the carve-out dependency-direction; forbid dedup/dangling/multi-oracle scenarios).
