Mechanism (adversarial-eval design "4b", in `harness/autowork_daemon.py`): at startup `run_daemon` captures `_daemon_source_sha(_reload_paths)` over its own source SET = `autowork_daemon.py` + daemon-scope imports (`brief_status`, `planner.staging`, `autowork_parallelism`, `selfheal`); at the top of each loop iteration `_should_reload_daemon(state_dir, startup_sha)` — gated on IDLE (zero `*.pid` in `_running_dir`, not paused/full_stop, no rebuild job) — recomputes the sha and, if changed, the loop emits a `daemon_source_changed` ledger row and `return 0`s so `scripts/run-autowork.sh` RESPAWNS fresh bytecode. NOT in-PID os.execv (rejected: higher blast radius). Oracle `tests/harness/test_daemon_self_reload_on_source_change.py` = 11/11 GREEN in real env.
