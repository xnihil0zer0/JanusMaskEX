# Title

ngv2/poc_authenticity_gate.py -- NEW pure, deterministic AST classifier that distinguishes a PoC which exercises the REAL target software from a self-contained mock/reimplementation, and forbids a "confirmed" verdict for mocks. In the NobleGreed bug-bounty pipeline, some generated PoCs were found to REIMPLEMENT or MOCK the target's vulnerable logic in a self-contained script -- starting a local mock HTTP server, or defining the vulnerable function/route locally -- and "detonate" against their own copy, yielding verdict=confirmed without ever exercising the real target. That is a false positive. This module is a deterministic gate that classifies a PoC's authenticity from its source text and returns may_confirm=False whenever the PoC is a self-contained mock, so the verdict path can refuse to confirm it.

# Scope

CREATE the NEW single-file module `ngv2/poc_authenticity_gate.py` (NGv2 external-target task -- `working_dir` = /home/xnihil0zer0/NobleGreedv2). The module is PURE and stdlib-only (`ast` plus `typing`): NO network, NO disk I/O, NO clock, NO randomness, NO uuid, NO subprocess, NO MCP, NO third-party import, and NO import of any sibling `ngv2/**` leaf. It operates ONLY on the `poc_source` string passed in (so it is differential-fuzzable and byte-stable). The primary function is `classify_poc_authenticity(poc_source: str, target_import_names: list[str]) -> dict`, returning a fixed-shape dict with exactly the keys `mode`, `imports_target`, `defines_vuln_locally`, `issues_network_request`, `may_confirm`.

Classification logic, AST-based on `poc_source` (parsed once with `ast.parse`; a SyntaxError or empty source is treated as a self-contained mock -- it cannot be shown to exercise the real target):
- `imports_target` is True iff the PoC `import`s or `from`-imports any name listed in `target_import_names` (matching by top-level package or any dotted prefix) AND references that imported name somewhere in the body.
- `issues_network_request` is True iff the PoC makes an outbound HTTP/socket call via `requests`, `urllib`/`urllib.request`, `http.client`, or `socket`.
- `defines_vuln_locally` is True iff the PoC defines its OWN functions or classes that stand in for the vulnerable behavior (e.g. a `def vulnerable_route(...)`, a mock handler/class, or a locally started server) and does NOT import the target.
- `mode` is `real_target` when `imports_target` is True; else `network_live` when `issues_network_request` is True and it does not import the target but is not merely a local mock; else `self_contained_mock`.
- `may_confirm = (mode != "self_contained_mock")`.

The module is reachable/wired by being importable into the NobleGreed verdict path (the verdict/detonation code can `from ngv2.poc_authenticity_gate import classify_poc_authenticity` and refuse to emit `confirmed` when `may_confirm` is False). The committed oracle `tests/ngv2/test_poc_authenticity_gate_wired.py` is the authoritative acceptance contract and proves the module is importable and behaves as specified.

CRITICAL AST-SAFETY CONSTRAINT: the sink/library names (`eval`, `exec`, `requests`, `socket`, `urllib`, etc.) appear ONLY as STRING-LITERAL data and in comments -- the module NEVER actually CALLS eval/exec/`__import__`/os.system/subprocess and uses NO decorators (the AST enforcer bans those). The module classifies source TEXT; it never executes the PoC.
