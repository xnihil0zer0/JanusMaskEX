# Title

User-friendly, type-safe, saveable WebUI configuration with role-to-model assignment and an expanded, OpenAI-compatible + Anthropic + codex-CLI model backend registry. The epic decomposes into five leaves wired as a DAG: a typed config schema + server-side validator (schema), a model backend registry (backends), the WebUI typed-widget + role-dropdown + api-key rendering and save wiring (ui), a sandboxed filesystem-browse endpoint + picker modal (fs-browse), and an end-to-end save/validation/lock test leaf (e2e). schema and backends land first (no UI dependency); ui depends on both; fs-browse depends on schema (it serves the path-typed fields); e2e depends on all four.

# Scope

Build a single typed schema that drives BOTH server-side validation AND WebUI field rendering on the LIVE stdlib-`http.server` operator sidecar (`tools/webui_server.py`, run as `python -m tools.webui_server --host 127.0.0.1 --port 8765 --state-dir state --logs-dir logs`), replacing the today's ad-hoc per-field config writes (`put_config_autowork`/`put_config_control` in `tools/webui_control.py`, and the raw JSON dump shown by the `#/config` page in `tools/webui_static/app.js`). NOTE: `webui/app.py` is a DEAD Flask tree — do NOT target it. The live surface is stdlib `http.server` (no Flask): GET routes in `tools/webui_server.py:WebUIHandler._dispatch_get`, mutations through `_dispatch_mutation` (auth + CSRF) resolving to `ControlHandlers` methods (`tools/webui_control.py`) returning `(status, body)` tuples named in the `_dispatch_post`/`_dispatch_put` class-attribute dispatch tables; the frontend is a vanilla-JS SPA in `tools/webui_static/`. Deliver:

1. **Typed schema + validator** (NEW `harness/webui_config_schema.py`): one declarative field list, each field tagged with a type (`int`/`float`/`str`/`bool`/`path-file`/`path-dir`/`enum`) plus bounds/choices; a server-side `validate_config()` that coerces+validates every field, rejects invalid input with a per-field error map, AND enforces two cross-field rules — (a) DUAL-AGENT roles (those whose RoleSpec.dual is True, e.g. `synthesis.active_agents`) must have two DIFFERENT chosen agents (reject save otherwise), and (b) any role assigned to an API-backed provider whose API-key field is empty is rejected (provider-locked-unless-keyed); plus `atomic_save_config()` writing config.yaml via temp-file + `os.replace`.

2. **Backend registry** (NEW `harness/model_backends.py` + NEW `harness/secrets_store.py`): a registry unifying every selectable model backend behind a stable spec; ONE OpenAI-style backend class parameterized by `(base_url, api_key_env, model_id)` covering OpenAI, the Gemini OpenAI-compatible endpoint, and the 5 Chinese providers (DeepSeek/Moonshot-Kimi/Zhipu-GLM/Qwen-DashScope/MiniMax from `_autowork_scratch/CHINESE_API_RESEARCH.md`); an Anthropic backend (its own SDK); a **codex CLI** backend mirroring the existing CLI-invoked agent pattern (`config.yaml agents:` block + `harness/orchestrator.py:_build_agent_command`'s generic `command`+`args` contract). Secrets persist in gitignored `state/secrets/api_keys.json` (mode 0600), never in config.yaml or any committed file.

3. **WebUI rendering + save** (EDIT whole-file `tools/webui_control.py` + `tools/webui_server.py` + `tools/webui_static/app.js`): a `ControlHandlers.get_config_schema()` GET handler (route `GET /api/config/schema` in `_dispatch_get`) serving `{fields, roles, providers, values, keys_present}`; a `ControlHandlers.post_save_typed_config(body)` mutation (table entry `'/api/config/typed': ('post_save_typed_config','body')` in `_dispatch_post`) that saves api keys via `secrets_store.save_secret` FIRST, then calls `validate_config` then `atomic_save_config`, returning success or `(400, {field_errors})`; and an `app.js #/config` typed-config view rendering each schema field with the correct widget (number/text/checkbox/enum-dropdown/path-with-Browse-button), a model-selection DROPDOWN per role + TWO dropdowns for dual-agent roles, an API-key `<input type=password>` per provider, `disabled` on any keyless api-backed provider `<option>` (client nicety) AND reject server-side, wired via the existing `api()` token+CSRF fetch wrapper.

4. **Filesystem-browse endpoint + picker** (EDIT whole-file `tools/webui_control.py` + `tools/webui_server.py` + `tools/webui_static/app.js`): `ControlHandlers.get_fs_list(query)` + route `GET /api/fs/list?path=` (in `_dispatch_get`) returning directory entries (name, is_dir) for path-typed fields, sandboxed to the control handlers' `repo_root` (the repo root) with traversal/symlink-escape rejected; a frontend picker in `app.js` that lists entries and fills the field on selection.

5. **E2E** (NEW `tests/webui/test_typed_config_e2e.py` as a leaf deliverable AND its own oracle is the committed test): drive the LIVE stdlib-http.server sidecar (spun up in-thread on an ephemeral port, `urllib.request` with operator token + CSRF nonce) through a valid save, an invalid-type save (rejected per-field), a dual-agent-same save (rejected), a role→keyless-provider save (rejected) then key-unlock, and the sandboxed fs-browse.

Meta task types: leaf-1/leaf-2 = `harness_plumbing` (NEW modules under harness/, not on `_NEVER_AUTO_APPROVE`); leaf-3/leaf-4 = `webui` EDIT (whole-file `tools/webui_control.py` + `tools/webui_server.py` + `tools/webui_static/app.js` — all NEW methods/routes ride as ADDITIVE nodes; never-patch-class-methods); leaf-5 = `integration`.

# Non-Goals

No edits to any `_NEVER_AUTO_APPROVE` file (`harness/orchestrator.py`, `harness/autowork_daemon.py`, `harness/git_integration.py`, `harness/paths.py`, `harness/interceptors.py`, `harness/selfheal.py`, `harness/agent_jail.py`, `harness/dbus_proxy.py`, `services/**`). `tools/webui_control.py`, `tools/webui_server.py`, and `tools/webui_static/app.js` are NOT on that list — they are the editable live surface. NO edits to the dead Flask tree `webui/app.py` or `webui/templates/**`. Specifically: the NEW backend registry is a standalone module that the orchestrator MAY later consume; this epic does NOT wire the registry into `harness/orchestrator.py:_build_agent_command` or the spawn loop (that is an owner-gated hand-edit, since orchestrator.py is deny-listed). No live LLM API calls, no real network egress in any tested path — backend specs are constructed/validated, not invoked; the OpenAI/Anthropic clients are built but a live `.chat()` is NOT asserted. No committing of any API key or secret to git (secrets live only in gitignored `state/secrets/`). The `/api/fs/list` endpoint stays loopback-only and rooted at the control handlers' `repo_root`; no arbitrary system traversal. No rewriting of existing class method bodies (never-patch-class-methods); add NEW methods/routes/cards as additive nodes. WebUI stays loopback-only, token + CSRF posture unchanged. integration: leaves 1-4 are unit-scoped (each drives the live sidecar in-thread); only leaf-5 is the cross-leaf integration test.
