Contract: ngv2.debate_router is a pure, deterministic, stdlib-only triage router that decides how a GraphMERT-scored vulnerability finding should be handled, distilled from the legacy debate_pool routing logic (the LLM/MASFactory debate machinery is intentionally OUT OF SCOPE). It exposes two module-level float constants AUTO_SUBMIT_THRESHOLD = 0.9 and AUTO_REJECT_THRESHOLD = 0.1. route_finding(finding: dict) -> str returns one of exactly three string literals: 'auto_submit' if the finding's confidence is STRICTLY GREATER THAN AUTO_SUBMIT_THRESHOLD, 'auto_reject' if STRICTLY LESS THAN AUTO_REJECT_THRESHOLD, and 'debate' otherwise (including the exact boundary values 0.9 and 0.1, which route to 'debate'). The confidence is read from finding['graphmert_confidence']; if that key is absent or None, route_finding falls back to scanning finding.get('grounding_evidence', []) for the first dict with layer == 'graphmert_v4' and uses its 'tp_probability' value; if no confidence can be resolved it defaults to 0.5 (which routes to 'debate'). DebateFinding is a dataclass constructed from a single dict argument, DebateFinding(finding: dict), that extracts and stores the following attributes with these exact defaults when keys are missing: finding (the original dict), graphmert_confidence (default 0.5), code_window (default ''), file (default ''), line (default 0), cwe (default ''), description (default ''), grounding_evidence (default []), confidence (default 'MEDIUM', a coarse grounding label distinct from the numeric graphmert_confidence). The module performs no I/O, no network, no LLM, no clock/random use, and imports only the Python standard library.

Per-round rules: taint_confirmed = any evidence status=='taint_confirmed' -> analyst verdict 'EXPLOITABLE' conf 0.85 else 'UNCLEAR' conf 0.4; known_fp = any status=='known_fp', corroborated = any status=='corroborated' -> fp_detector 'LIKELY_FP' conf 0.9 if known_fp elif 'UNLIKELY_FP' conf 0.7 if corroborated else 'UNCLEAR' conf 0.3; exploit_validator 'SUBMIT' conf 0.8 if (taint_confirmed and graphmert_confidence>0.5) elif 'REJECT' conf 0.5 if known_fp else 'INVESTIGATE' conf 0.5. Consensus: sum confidence into submit_weight (verdicts EXPLOITABLE/SUBMIT/UNLIKELY_FP), reject_weight (NOT_EXPLOITABLE/REJECT/LIKELY_FP), investigate_weight (everything else) across ALL rounds; total = sum or 1 if zero; if submit/total>0.5 -> final 'SUBMIT' conf submit/total; elif reject/total>0.5 -> 'REJECT' conf reject/total; else 'NEEDS_INVESTIGATION' conf investigate/total. - `ngv2-rl-debate-weights` -> `ngv2/rl_debate_weights.py` (gate: stateful_fuzz; meta_task_type: stateful_fuzz). Exposes: RLState, DEFAULT_ROLES, UCB_C. Contract: ngv2.rl_debate_weights is a pure, deterministic, in-memory multi-armed-bandit (UCB1) controller that learns debate-agent weights from triage outcomes; it has NO file I/O, NO clock, and NO randomness (the legacy JSONL/datetime persistence is dropped). Class RLState() constructs empty with four public attributes: records (list), agent_stats (dict), cwe_stats (dict), round_stats (dict). After construction (before any records) agent_stats is seeded {role: {'correct':0,'total':0} for role in DEFAULT_ROLES} and cwe_stats/round_stats are empty dicts. record_outcome(debate_result: dict, actual_outcome: str) -> None ingests one debate and recomputes all stats; it reads debate_result keys 'finding_cwe' (str, default '' bucketed as 'unknown' when falsy), 'final_verdict' (str), 'debate_rounds' (list of round dicts each with 'arguments': list of {'role','verdict','confidence'}); n_rounds = len(debate_rounds). actual_outcome is 'TP' or 'FP'. Stats semantics: round_stats[n_rounds] = {'correct','total'} where a debate is verdict-correct iff (final_verdict=='SUBMIT' and outcome=='TP') or (final_verdict=='REJECT' and outcome=='FP'); agent_stats[role] = {'correct','total'} aggregated over every argument across all rounds, where an agent is correct iff (agent verdict in {'EXPLOITABLE','SUBMIT','UNLIKELY_FP'} and outcome=='TP') or (agent verdict in {'NOT_EXPLOITABLE','REJECT','LIKELY_FP'} and outcome=='FP'); cwe_stats[cwe][role] = {'correct','total'} is the same per-CWE breakdown (cwe taken from finding_cwe, falsy -> 'unknown'). get_weights(cwe: str='') -> dict returns {role: float} over exactly DEFAULT_ROLES: cold-start (total agent observations across agent_stats < 10) returns uniform {role: 1.0}; otherwise per role weight = accuracy + UCB_C*sqrt(log(total_obs)/role_total) (a role with total==0 gets weight 1.0), then all weights are normalized to sum to float(len(DEFAULT_ROLES)) == 3.0; when cwe is non-empty the per-CWE stats are used (falling back to agent_stats for that role if the cwe/role bucket is absent). get_stats() -> dict returns {'total_records': len(records), 'agent_accuracy': {role: {'accuracy','correct','total'}}, 'round_accuracy': {str(n): {'accuracy','correct','total'}}, 'cwe_coverage': list(cwe_stats keys), 'weights': get_weights()} where accuracy = correct/total or 0 when total==0. All methods are pure w.r.t. process state (no disk/network/clock) and recompute deterministically from records.
